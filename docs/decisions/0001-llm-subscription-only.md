# ADR-0001: LLM только через подписку Claude Pro, без API-ключа

- **Статус:** принято
- **Дата:** 2026-10-18

## Контекст

Владелец не хочет никаких дополнительных расходов на LLM. У него есть подписка Claude Pro, через которую работает Claude Code (`claude -p`). Если в окружении есть `ANTHROPIC_API_KEY`, Claude Code молча переключается на оплату по API — это реальные деньги без предупреждения.

ToS подписки разрешают личное использование владельцем, но не обслуживание других пользователей через его подписку.

## Решение

1. Все вызовы LLM идут через `LLMProvider`; сейчас единственная реализация — `ClaudeCodeSubscriptionProvider` (subprocess `claude -p --output-format json`).
2. **Единственная точка входа — `LLMGate`** (`backend/app/llm/gate.py`). Прямые вызовы провайдера в других местах запрещены.
3. `ANTHROPIC_API_KEY` никогда не добавляется, не читается и не требуется:
   - каждый процесс при старте вызывает `enforce_no_api_key()` (`app/core/env_guard.py`) — переменная удаляется с warning в логе;
   - subprocess `claude` запускается только с `sanitized_env()`.
4. Subscription-провайдер разрешён **только для `role=owner`**. Для других пользователей — только будущий `AnthropicApiProvider`, иначе отказ.
5. При ошибке лимита — **стоп**: `LlmState.paused_until`, ровно одно сообщение в Telegram «лимит, продолжу позже», задачи остаются в очереди и продолжаются после сброса.
6. Дневные потолки вызовов отдельно на `parse`, `score`, `draft` — чтобы не выбирать лимит подписки целиком.
7. Перед любым вызовом LLM работает дешёвый префильтр без нейросети.

## Последствия

- **+** Нулевая стоимость LLM для владельца; невозможно случайно уйти в платный API.
- **+** Абстракция провайдера позволяет позже открыть сервис другим через API-ключ без переписывания конвейера.
- **−** Пропускная способность ограничена окнами лимитов Claude Pro (~5 ч + недельный) → очередь, приоритизация по keyword-score.
- **−** На VPS нужен `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`), который может истекать → healthcheck и уведомление admin.
- Тест `test_api_key_is_removed_from_env` защищает правило от регрессий.
